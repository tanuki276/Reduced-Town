# 品質基準 — 「チープにしない」ための強制ルール

Like Homes のチープ感の正体は、技術不足ではなく「平坦さ・均一さ・繰り返しの露出」だった。Reduced-Town ではこれを最初から仕様として禁止する。この文書の項目は Stage 1 の完了条件に含まれる。生成AIへの指示でも、この文書を仕様書と一緒に必ず渡すこと。

## 1. 素材

- 建物・小物は CC0 実アセットを実形状・実テクスチャのまま使う。単色ボックスや頂点カラーの近似で代用しない
- テクスチャにはミップマップを有効化し、遠景でチラつかせない
- 同じ建物をそのまま並べない。色バリエーション（Kenney Suburban の variation テクスチャ等）と回転・反転で最低でも見た目を分散させる

## 2. 照明と空気

- 太陽光は真上から均一に当てない。角度を付け、暖色寄りの色と影を持たせる
- 空は単色クリアにしない。グラデーションのある空（ProceduralSkyMaterial 等）と、空の色に合わせた距離フォグで奥行きを作る
- Godot のトーンマッパーは ACES または AgX を使い、露出は「白飛ばししない」側に寄せる。初期値のベタ塗りライティングのまま出さない
- GL Compatibility レンダラーでは SSAO や SSR は使えない。前提として割り切り、接地感は第3項の方法で作る

## 3. 接地感（物が浮いて見えるのを防ぐ）

- 全ての静物は太陽の影を落とす。影なしの配置を禁止する
- 車・自販機・ゴミ箱などの小物の足元には、暗色の半透明プレーン等で接触影を足す（AO の代用）
- プレイヤーと車も影を落とす。影のないキャラクターは即チープに見える

## 4. 繰り返しの破壊

- 街灯・ベンチ・木・電柱などの反復小物は、回転・スケール（±10%）・色味（±5%）に個体差を付ける。全て同一の向き・同一サイズで並べない
- 街区ごとに小物の密度と種類に偏りを持たせる。全街区が同じ顔にならないこと
- 空き地・何もない平面を残さない。密度が低い場所は「意図的な広場」として舗装と縁石で形を作る

## 5. 動き

- 歩行アニメーションの再生速度は実際の移動速度に同期させる。足が滑る（フットスライディング）状態を完了としない
- 車はタイヤが回転し、前輪がハンドルに連動して切れる。車体の傾き（加速・旋回時の微小なロール／ピッチ）があれば尚よい
- カメラは完全固定にしない。歩行時の微小な上下動と、旋回時の滑らかな追従（lerp）を入れる。ただし酔うほどの揺れは禁止

## 6. 音

- 無音を禁止する。常時流れる環境音（風・遠くの交通のループ）を最低限入れる
- 足音、車のエンジン音（回転数でピッチが変わる簡易版でよい）を付ける
- 音源はフリー素材か生成音でまかない、出所を記録する

## 7. UI

- 絵文字をアイコンとして使わない。線画のベクターアイコン（SVG）に統一する
- フォントは1種類に統一し、HUD の余白と文字サイズに一貫した規則を持たせる
- 画面遷移とボタン反応には短いイージングを入れる。瞬間切り替えだけの UI にしない

## 性能との両立

- 上記はモバイル実機で 30fps を割らない範囲で適用する。影の解像度、フォグ距離、描画距離は実機で調整する調整値であり、見た目を守るために描画距離を極端に縮めることはしない
- 重くなったら「小物の個体差を減らす」のではなく「遠景の小物を間引く」で対処する。近景の質は最後まで守る

## 検証

- 各 Stage の完了判定では、街路レベル（プレイヤーの目線）のスクリーンショットを撮り、この基準の各項と照合する。起動エラーがないことやファイルが読み込めることは品質の証明にならない
